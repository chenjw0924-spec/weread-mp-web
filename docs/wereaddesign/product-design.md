# 微信读书文章归档 · 高保真界面设计

> 状态：设计稿（原型）
> 原型文件：`docs/weread/prototypes/index.html`（用浏览器直接打开即可，右下角「原型导航」可跳到任意状态）
> 视觉继承：`site/design-system.css` 与 `docs/web-tool/prototypes/proto.css` 的品牌 token

## 1. 定位与关键前提

- **一句话定位**：连接微信读书，把你已关注的公众号文章批量导出为 Markdown + ZIP。
- **主流程三步**：连接微信读书 → 选择文章 → 下载文件。普通用户路径中不出现「Cookie」「开发者工具」「复制粘贴」等操作。
- **实现前提（必须阅读）**：扫码登录必须由**服务端实际支持微信读书的扫码授权流程**，并在授权后建立可用连接。如果现有项目只接受手动 Cookie，单改页面无法实现扫码登录。
- **兜底原则**：普通用户的主流程保持扫码。即使技术验证发现扫码暂不可用，也**不得**把「打开开发者工具、复制 Cookie」作为默认补救方式；只能在明确标注为「高级/异常诊断」的旁路里、且用户主动进入时提供。

## 2. 信息架构（三步）

```
连接微信读书 ── 选择公众号 → 选择文章 ── 批量下载
   │ 未连接首页          │ 搜索/列表/筛选          │ 已选篇数 + 下载按钮
   │ 扫码页（等待/确认/成功/过期/失败）
   │ 连接成功后显示昵称 + 「已连接」
```

## 3. 页面与状态清单

### 3.1 连接微信读书（Step 1）

| 状态 | 界面 | 文案 |
|---|---|---|
| 未连接首页 | 居中卡片 + 主按钮 | 标题「连接微信读书」；副文「扫码登录后，即可查看你关注的公众号文章。」；按钮「扫码连接」；脚注「只用于读取你已关注的公众号内容，不接触其他数据，也不会上传文章内容。」 |
| 扫码页 | 左二维码 + 右操作说明 | 标题「用微信扫描二维码」；步骤 ① 打开微信，选择“扫一扫” ② 扫描页面上的二维码 ③ 按手机提示完成确认 |
| 等待扫码中 | 状态行（转圈） | 「等待扫码中」 |
| 已扫码待确认 | 状态行（脉冲） | 「已扫码，请在手机上确认」 |
| 连接成功 | 状态行（绿勾）+ 昵称胶囊 | 「连接成功」+ 显示微信读书昵称 |
| 二维码过期 | 二维码盖层 + 状态行 | 「二维码已过期，正在刷新…」，自动刷新后回到「等待扫码中」 |
| 扫码失败 | 二维码盖层 + 两个按钮 | 「扫码失败，请重新扫码」；按钮「重新扫码」「返回首页」，**不要求用户自行处理登录信息** |

连接成功后，页头右上角常驻「已连接 · 昵称」胶囊。

### 3.2 选择公众号与文章（Step 2）

| 状态 | 界面 | 文案 |
|---|---|---|
| 公众号列表 | 左侧栏，带搜索 | 「我的公众号」+「搜索公众号」；每项显示昵称与「N 篇可获取」 |
| 已选公众号 | 主区头部 | 公众号名 + 可获取日期范围提示「可获取日期范围：YYYY-MM-DD ~ YYYY-MM-DD（更早的内容可能无法获取）」，避免误以为能查全部历史 |
| 文章筛选 | 工具条 | 标题搜索 + 开始/结束日期 + 「清空筛选」 |
| 文章列表 | 逐行勾选 | 标题、日期、「含 N 张图片」；头部「全选当前结果」+「当前结果 N 篇 · 已选 N 篇」 |
| 空态（无内容） | 居中空态 | 「该公众号暂无可获取内容」「可能是这个公众号暂时没有可读取的文章。你可以换一个公众号再试试。」+「更换公众号」 |
| 空态（无匹配） | 居中空态 | 「没有找到匹配的文章」「换一个标题关键词或调整日期范围再试试。」 |
| 暂时无法读取 | 顶部提示条 | 「暂时无法读取这个公众号的文章，请稍后再试。」+「重新加载」 |

### 3.3 批量下载（Step 3）

| 状态 | 界面 | 文案 |
|---|---|---|
| 底部固定条 | 吸底 | 「N 篇已选」+「下载文章」（0 篇时禁用）；「勾选要导出的文章」 |
| 下载确认 | 弹窗 | 「下载 N 篇文章」；选项「同时下载图片」**默认关闭**，说明「把文章里的图片一并下载到 ZIP（默认关闭，关闭时图片保留原图链接）」；「取消」「开始下载」 |
| 导出进度 | 弹窗 | 进度条 + 「正在导出第 N / 总数 篇」+ 成功数 / 失败数统计 + 逐篇状态 |
| 完成（有失败） | 弹窗 | 「导出完成」+「N 篇成功 · N 篇未成功」；失败项给出**简短原因**（如「暂时无法读取这篇文章，已跳过」）+「重试失败项」 |
| 图片失败 | 弹窗内提示 | 「图片说明：有 N 篇文章的图片未能下载，已保留原图链接，Markdown 中仍可点击查看原图。」 |

### 3.4 连接过期（贯穿 Step 2）

- 遮罩层提示「连接已过期」+「登录状态已失效，请重新扫码连接。当前已选的文章会为你保留。」+ 显示「已保留 N 篇已选文章」+「重新扫码」。
- 重新扫码成功后，回到选择页，**已选文章与勾选状态原样保留**。

## 4. 文案与体验规范

- 全程使用**日常语言**说明下一步，禁止出现：Cookie、开发者工具、复制粘贴、接口 / API、会话 / Session、请求、风控等词。
- 错误信息一律给「下一步动作」，不给技术细节。例如：
  - 连接过期 → 「连接已过期，请重新扫码」
  - 需要手机确认 → 「已扫码，请在手机上确认」
  - 读取失败 → 「暂时无法读取这个公众号的文章，请稍后再试」
- 图片归档失败**不得静默丢图**：保留原图链接并向用户报告失败数量。
- 下载图片默认关闭，用户偏好可通过本地存储记住。

## 5. 视觉规范（原型执行标准）

- 主色 `#0c714b`、深绿 `#06452f`、lime `#dfff67`（强调）、纸面 `#ffffff`、画布 `#f7f9f6`、边线 `#dce5df`、次级文字 `#6d7a72`。
- 状态色：进行中蓝 `#2563eb`、失败红 `#dc2626`、警告琥珀 `#b45309`、等待灰 `#94a3b8`。
- 字体：标题 Arial Rounded MT Bold / PingFang SC 落回；正文 Inter / system-ui。
- 组件：按钮圆角 11px、卡片 16px、状态徽章胶囊；焦点可见（3px 绿色 outline）；支持 `prefers-reduced-motion`。
- 响应式：768px 下单列；侧栏不再吸顶；375px 下步骤条只保留数字。

## 6. 后续实施要点

1. **服务端扫码授权**：登录二维码、轮询登录结果、二维码过期刷新、授权后建立可用连接，全部由服务端支持（微信读书扫码授权流程）。
2. **可获取日期范围**：以服务端实际返回为准，前端不得臆造历史范围。
3. **失败重试**：下载失败项单独重试；图片失败保留原图链接。
4. **连接过期**：过期时冻结并保留当前选中集合，重新扫码后恢复。
5. **验收**：修改后跑通三步主流程与全部异常态；在 375 / 768 / 1440 宽度检查布局与键盘可访问性。
